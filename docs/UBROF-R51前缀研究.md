# IAR 8051 R51 元数据前缀研究记录

## 范围与限制

本记录仅描述本地取得的两个 IAR 10.20.1 / CC2530 R51 样本的可重复观察结果。原始 R51、D51、TI SDK 库字节均不进入仓库或 Actions artifact。

当前工具 `tools/audit_iar_ubrof_prefix.py` 只解析文件开头的模块标识、版本字段和连续 `0xC9` 属性链。它不是完整 UBROF 解析器，也不生成 REL，不恢复机器码或重定位。

## 两个真实样本的观察结果

| 项目 | `hal_key.r51` | `OSAL_FreePadApp.r51` |
|---|---:|---:|
| 模块名 | hal_key | OSAL_FreePadApp |
| 编译器版本字段 | 10.20 | 10.20 |
| 首个 C9 偏移 | 0x20 | 0x28 |
| 连续 C9 记录数 | 11 | 11 |
| C9 链结束偏移 | 0x184 | 0x18C |
| 下一字节 | 0x52 | 0x52 |

模块名长度增加 8 字节时，首个 C9 偏移及属性链结束偏移也相应增加 8 字节。两个样本的 C9 属性链都能按外层长度和内部 key/value 长度完整闭合。

共同属性包括 `__calling_convention=xdata_reentrant`、`__code_model=banked`、`__data_model=large`、`__core=plain` 和 `__dptr_size=16`。

## 当前解析规则（仅限已观察前缀）

- 文件以观察到的 7 字节前缀开始，随后是 1 字节模块名长度及 ASCII 模块名。
- 后续 11 字节暂时作为不解释的头部字段保留。
- 随后读取 1 字节版本字符串长度及 ASCII 版本字符串。
- `0xC9` 记录使用 4 字节大端长度；payload 内含 4 字节大端 key 长度、key、4 字节大端 value 长度、value。
- 遇到第一个非 `0xC9` 字节即停止，不猜测其含义。

以上是对两个真实样本的经验性解析，不代表已证明所有 IAR UBROF 版本、目标架构或记录类型均遵循相同布局。

## 待验证

1. 识别并验证 `0x52` 及其后续记录边界。
2. 将 R51 记录与 S51/LST 中的段、函数和符号逐项交叉验证。
3. 独立确认代码段原始字节、符号偏移和重定位表。
4. 在 ABI、bank 布局和运行时模型均有证据后，再讨论单模块 REL 转换。

当前没有任何证据支持“已完成 R51 转换”或“已生成可用 SDCC 固件”的结论。
